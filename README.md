## 📋 Project Overview

**Business Problem:** Late deliveries and high return rates increase operational costs
and customer churn by 15–20% annually.

**Solution:** An end-to-end AI system that predicts delivery delays with **78% accuracy**,
enabling proactive intervention — now exposed as a production-ready REST API with
a live analytics dashboard.

**Impact:** Estimated savings of **₹51,800/month** through 15% reduction in SLA breaches
and optimised warehouse operations.

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                        CLIENT LAYER                             │
│   Browser Dashboard (dashboard.html)  │  External Systems / BI  │
└──────────────────────────┬──────────────────────────────────────┘
                           │ HTTP / REST
┌──────────────────────────▼──────────────────────────────────────┐
│                      FLASK REST API  (app.py)                   │
│                                                                 │
│  /api/auth          /api/orders        /api/predictions         │
│  /api/analytics     /apidocs (Swagger)  /health                 │
│                                                                 │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────────────┐    │
│  │  Auth BP     │  │  Orders BP   │  │  Predictions BP    │    │
│  └──────────────┘  └──────┬───────┘  └────────┬───────────┘    │
│                            │                   │                │
│                    ┌───────▼───────────────────▼───────┐        │
│                    │     Service Layer                  │        │
│                    │  analytics_service.py              │        │
│                    │  prediction_service.py  ←──────────┼──────┐ │
│                    └───────────────┬───────────────────┘      │ │
│                                    │                          │ │
└────────────────────────────────────┼──────────────────────────┼─┘
                                     │ SQLAlchemy ORM           │ joblib
┌────────────────────────────────────▼──────────┐   ┌───────────▼──────┐
│            PostgreSQL Database                 │   │  Random Forest   │
│                                               │   │  .pkl Model File  │
│  customers │ warehouses │ orders              │   └──────────────────┘
│  predictions │ alerts │ kpi_snapshots         │
│  audit_log  │ (views & triggers)              │
└────────────────────────────────────────────────┘
```

**Data flow for a new order:**
1. Client `POST /api/orders/` with order details
2. Order saved to PostgreSQL
3. `PredictionService.predict()` runs the Random Forest model
4. Prediction + risk category saved to `predictions` table
5. If **High Risk** → auto-create alert in `alerts` table
6. Response returns order + prediction to client in one round-trip

## 🚀 Running Locally — Step-by-Step

### Option A: Without Docker (SQLite, simplest)

#### Prerequisites
- Python 3.11+
- Git

#### 1. Clone and set up virtual environment
```bash
git clone <your-repo-url>
cd ecommerce-ops

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

#### 2. Install dependencies
```bash
pip install -r requirements.txt
```

#### 3. Configure environment
```bash
cp .env.example .env
# .env is pre-configured for SQLite — no changes needed for local dev
```

#### 4. Generate dataset and train the ML model
```bash
# Step 4a: Generate ecommerce_data.csv (5,000 orders)
python ecommerce_ai_project.py

# Step 4b: Train Random Forest and save to models/
python train_and_save_model.py
```

#### 5. Start the API server
```bash
python app.py
# API running at: http://localhost:5000
# Swagger docs:   http://localhost:5000/apidocs
```

#### 6. Open the dashboard
Open `frontend/templates/dashboard.html` in a browser.
Login with `admin / admin123`.

## 📊 Model Details

### Algorithm: Random Forest Classifier
- `n_estimators=100`, `max_depth=10`, `random_state=42`
- Trained on 3,500 orders, evaluated on 1,500

### Features (in order)
| # | Feature | Importance | Business Meaning |
|---|---------|-----------|-----------------|
| 1 | `distance_km` | 28.4% | Farther orders delay more |
| 2 | `warehouse_load` | 23.7% | Overloaded warehouses cause delays |
| 3 | `past_delays` | 18.9% | History predicts future |
| 4 | `order_items` | 15.3% | More items = longer packing time |
| 5 | `warehouse_*` (OHE) | 13.7% | Location-specific performance |

### Performance
| Metric | Score |
|--------|-------|
| Accuracy | 78.3% |
| Precision | 76.5% |
| Recall | 72.1% |

### Risk Categories
| Probability | Category | Action |
|------------|----------|--------|
| ≥ 60% | 🔴 High | Auto-alert, priority carrier |
| 30–60% | 🟡 Medium | Monitor closely |
| < 30% | 🟢 Low | Standard processing |

## 💡 Key Interview Points

| Topic | What to Say |
|-------|------------|
| **Why Random Forest?** | Handles mixed feature types, gives feature importance natively, robust to outliers vs Logistic Regression (baseline +3% accuracy) |
| **Why 78% accuracy?** | Dataset is synthetically generated with realistic noise; real-world data with richer features (weather, traffic) would improve this |
| **Precision vs Recall tradeoff** | High precision (76.5%) chosen to minimise false alarms for ops team — we only flag orders we're confident about |
| **API design choice** | Blueprints for separation of concerns; JWT over sessions for stateless, scalable design |
| **Rule-based fallback** | API still works without the .pkl file — degrades gracefully, critical for deployment robustness |
| **Database views** | `v_current_kpis`, `v_warehouse_performance`, `v_city_delay_summary` pre-aggregate for fast dashboard queries |
| **Extensibility** | Add Celery tasks for async batch scoring; add Alembic migration for schema changes; swap RF with XGBoost in `prediction_service.py` only |
